# Phase 1 MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Phase 1 start tracks offline: HL-first history with provenance + Parquet cache, SQLite runs, regime labels, uptrend/downtrend search ranked by net PnL / total return, multi-candidate Phase-2 export.

**Architecture:** Thin `hypervector` package with pure ranking/metrics/regime logic separate from I/O. History is cache-first Parquet under gitignored `data/`. Adapters accept injectable fetch functions so offline fixtures prove merge/provenance without network. VectorBT used for portfolio metrics on classic baselines; Optuna/majors/book/full pine deferred.

**Tech Stack:** Python 3.13, VectorBT 1.1.0, pandas, pyarrow (via vectorbt/pandas), SQLite stdlib, pytest, uv.

## Global Constraints

- Symbol MVP: BTC / BTC-PERP only; config-shaped for majors later.
- TF MVP: 1m; lookback floor ≥30d, default 90d, optional 180d.
- Rank trade tracks by **net_pnl** then **total_return_pct**; report Sharpe, trade count, W/L, win %, drawdown.
- No risk gates / regime vetoes unless configured (default off).
- Offline fixtures only in CI; live HL/Binance/Bybit best-effort behind adapters.
- No Phase 2/3 live trading; no Optuna hard dependency; no full pine day-one.
