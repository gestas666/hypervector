the existing native router and dynamic account, with exact source provenance,
fixed outcome seals and complete reproducible account artifacts.

**Architecture:** bind captured study identities to authenticated economic
inputs; share existing account serialization/streaming; add a captured-source
caller which authenticates its calendar and source selections before native
account evaluation. The complete source-to-provider calendar assembler remains
an explicit integration requirement, not an assumption hidden by writer tests.

provider/routing/account modules, deterministic XZ artifacts and pytest. Use
the isolated prospective checkout at baseline `a219e286`; no runtime deployment,
collector changes, financial process actions or sealed outcome evaluation.
