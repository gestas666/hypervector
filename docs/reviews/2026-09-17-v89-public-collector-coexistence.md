the OS sandbox denies network and writes to live/runtime/source-study roots.

guard's decisions. Original four-peer health reads are sequential, so this is
not an atomic multi-peer health snapshot.

## Newly reproduced full-day limitation

A real `NativeMinuteQuery` for 1,440 one-minute candles produces 165,601 bytes
of deterministic response body. Its minimal acknowledgement already requires
220,857 bytes, exceeding the research relay's 65,536-byte frame bound. Calling
the actual `Peer.send` rejects it before writing any pipe bytes. The standalone
probe reproduced the same result exactly.

This is a limitation of the offline qualification relay, not evidence that the
currently running collectors or live strategy are failing. It prevents using
this smaller-window success as proof of full-day historical recovery. The next
highest-value implementation is bounded delivery of full-size receipts, with
exact ownership, integrity, original deadline and cancellation tests, followed
by full-day original-loop qualification. Merely shortening historical queries
would not satisfy that requirement.
