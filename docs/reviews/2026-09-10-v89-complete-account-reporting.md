# Complete historical account reporting qualification

The reporting pipeline is implemented and reproduced from frozen source
`34004579e2cb21d13c55e01c47fa6f69e70d76ff`. It authenticates a complete original
matrix before analyzing any case, independently reconciles each complete account,
retains all original case reports and publishes every single-axis comparison.
This qualifies reporting mechanics; no complete historical account result or
profitable live improvement is established by this review.

The per-case reader binds the expected source/cost/clock/allocation identity and
original allocation fingerprint. It authenticates source and output files before
and after analysis and reruns the independent Decimal accounting audit. Path
metrics retain full marked equity, the original earlier/later periods, daily
contributions, drawdown and time-weighted capital use. Terminal positions retain
their marks and paid fees/funding; reporting does not force a closing trade.

Every original source-priced proposal is traced to a native routing exclusion or
committed account disposition. Accepted proposals reconcile to closed or open
trade contributions. Routine empty provider evaluations are not counted as missed
trades. Full-window asset, strategy and direction groups retain every declared
label, including assets with zero activity. Marked positive-day concentration is
reported separately from closed-winner concentration.

The matrix catalog binds all 48 original case identities, four source pairs,
registered upstream files, exact replay archive and commit metadata. The publisher
requires each case to retain its expected upstream references, compares the fresh
independent result with the retained audit, and reauthenticates all consumed files
before publishing a complete immutable directory. Partial and conflicting results
cannot create a success-shaped final directory. Existing output is not replaced.

The comparison retains canonical case order and 144 single-axis pairs: four binary
axes and all three pairwise cost contrasts. The primary contrast remains first
core/full-prefix XYZ/adverse cost/recorded clock/control versus equal allocation.
Negative results remain results. Undefined ratios remain null. Replay-engine
provenance and reporting-source provenance are recorded separately.

The CLI is `scripts/v89_historical_account_matrix_report.py`. It requires explicit
repository, matrix report path/bytes/SHA-256, replay archive/commit, reporting
archive/commit and a new output directory. Original registration/configuration
reads remain report-only; it constructs no signer or execution client. All data
paths resolved from a different worktree must refer to the original repository.
